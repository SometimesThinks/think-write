> # ThinkWrite 시스템-아키텍처

## 1. 개요

ThinkWrite는 Next.js 단일 애플리케이션 안에서
프론트엔드 편집기와 서버 계층의 책임을 분리하는 구조를 채택한다.

MVP 기준 핵심 기능은 다음 세 가지이다.

- 학습 언어 설정
- 고스트 자동 완성 (Ghost Autocomplete)
- BYOK 기반 provider 연동

## 2. 시스템 구성 요소

### 2.1 편집기 UI

- 사용자의 텍스트 입력 처리
- 고스트 텍스트 표시
- `Tab`, `Esc` 등 키보드 상호작용 처리

### 2.2 설정 UI

- 모국어 및 목표 언어 설정
- provider 선택
- API Key 입력 및 저장 상태 표시 (원문 재노출 없음)

### 2.3 서버 계층

- 학습 언어 설정값 반영
- completion 요청 처리
- provider 호출
- API Key 암호화 저장, 조회 상태 제공, 삭제, provider 호출 시 사용

### 2.4 LLM Provider

- 초기 MVP는 OpenAI `gpt-5-nano`를 사용하며, 이후 OpenAI 외 provider 확장을 고려한다.
- 서버 계층은 adapter를 통해 provider를 호출

## 3. 핵심 흐름

### 3.1 학습 언어 설정

- 사용자가 모국어와 목표 언어를 설정함
- 설정값은 클라이언트 상태로 유지되고, 요청 시 함께 전달됨
- 이후 completion 요청에 해당 설정값이 반영됨

### 3.2 고스트 자동 완성 (Ghost Autocomplete)

- 사용자가 편집기에서 텍스트를 입력함
- 입력이 잠시 멈추면(Debouncing 처리) completion 요청 생성
- 서버 계층이 현재 문맥과 설정값을 바탕으로 provider 호출
- 응답 결과(SSE 방식의 스트리밍 등)를 편집기에서 고스트 텍스트로 표시
- 사용자는 `Tab`으로 수락하거나 `Esc`로 무시함

### 3.3 BYOK 기반 요청 처리

- 사용자가 provider와 API Key를 서버 계층에 등록함
- 서버는 API Key를 암호화하여 영구 저장하고, 원문은 다시 반환하지 않음
- completion 요청 시 서버가 저장된 Key를 사용해 provider를 호출함
- 잘못된 Key 입력 또는 인증 실패 시 전역 오류로 반환함

## 4. 구현 구조

- `app/`: 사용자 인터페이스 및 API route
- `src/server/use-cases/`: 기능 단위 서버 로직
- `src/server/services/`: 공통 서비스 및 정책
- `src/server/providers/`: provider adapter 구현
- `src/server/lib/`: 공통 유틸리티

## 5. 설계 원칙

- 편집기 인터랙션과 서버 로직의 책임 분리
- 특정 provider에 종속되지 않는 구조 유지
- 사용자의 글쓰기 흐름을 우선하는 응답 처리
- 추후 멀티 프로바이더 확장이 가능한 구조 유지
- 전역 설정 오류와 editor 내부 ghost 흐름 오류를 분리해 처리한다
