- 실행 체크리스트 문서에서 editor foundation과 language settings의 완료된 항목을 반영했다.

## Why it matters
- 이제 이 프로젝트는 단순한 화면 시안이 아니라, 실제 입력과 커서 위치를 바탕으로 자동완성 요청을 만들 수 있는 단계로 올라갔다.
- `prefix`/`suffix`를 눈으로 직접 확인할 수 있어서 이후 debounce, ghost state, provider 호출을 붙일 때 요청 설계를 추측하지 않고 검증할 수 있다.
- 같은 검증 함수를 client와 server가 공유하게 되면서 preview에서 본 요청 형식과 API가 받는 형식이 어긋날 가능성이 줄었다.
- 학습 관점에서도 Tiptap editor 연결, selection 기반 문맥 추출, client/server 계약 공유라는 핵심 포인트가 한 커밋에 모였다.

- Tiptap selection 위치를 그대로 사용했을 때 문단 경계나 줄바꿈이 자동완성 품질에 어떤 영향을 줄까?

- 검증 로직을 shared로 옮긴 결정은 어떤 장점이 있고, 반대로 server 전용 규칙이 생기면 어디서 다시 분기해야 할까?
- localStorage 기반 language settings는 MVP에 적절하지만, 이후 서버 동기화가 필요해지면 어떤 경계부터 바꿔야 할까?

## Interview framing
- 정적인 editor shell에서 멈추지 않고, 실제 커서 상태를 읽어 자동완성 요청 payload를 확인할 수 있는 단계까지 수직 슬라이스로 올렸다.
- 자동완성 기능을 붙이기 전에 `prefix` / `suffix`가 실제로 어떻게 계산되는지 시각화해서 이후 provider 연동 디버깅 비용을 줄였다.
- 검증 로직을 shared로 옮겨 preview UI와 API route가 같은 request contract를 따르게 만들었다.
- MVP에서는 rich text를 넓히지 않고 text-first 편집 흐름에 필요한 최소한의 editor surface만 열었다.
