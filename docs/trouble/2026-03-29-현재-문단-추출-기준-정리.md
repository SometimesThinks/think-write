# 현재 문단 추출 기준 정리

- 작성일: 2026-03-29
- 상태: 진행 중
- 관련 범위: editor foundation, ghost complete, request context

## 1. 문제 상황

Ghost Complete 요청에 사용할 `prefix` / `suffix`를 처음에는 문서 전체 기준으로 읽고 있었다.

```ts
const prefix = doc.textBetween(0, selection.from, '\n\n', '\n');
const suffix = doc.textBetween(selection.to, doc.content.size, '\n\n', '\n');
```

이 방식은 구현은 단순하지만, 현재 커서가 있는 문단보다 훨씬 넓은 범위를 요청 문맥으로 보내게 만든다.

---

## 2. 처음 헷갈렸던 지점

초기에는 “현재 문단을 구분하는 기준이 그냥 줄바꿈인가?”라는 관점으로 접근했다.

그러다 Tiptap 문서를 볼 때 `paragraph` 관련 설명이 스타일링 중심으로 읽혀서,
`paragraph node`가 문서 구조 단위라는 점이 바로 와닿지 않았다.

즉, 헷갈린 지점은 다음과 같았다.

- 화면상 줄바꿈과 문서 구조상의 문단을 같은 것으로 보기 쉬움
- `paragraph` 문서를 봐도 UI/스타일 설명처럼 보여 구조 기준으로 바로 연결되지 않음

---

## 3. 정리된 기준

현재 문단의 기준은 **문자열 줄바꿈 자체**보다 **현재 selection이 속한 paragraph node**로 잡는 것이 맞다.

실제로 Ghost Complete에 필요한 것은:

1. 커서가 속한 현재 문단 찾기
2. 그 문단 안에서만 `prefix` / `suffix` 계산
3. 문서 전체는 길이 표시나 전체 상태 파악 용도로만 유지

즉, 구현 기준은 다음처럼 정리된다.

- `documentText`: 문서 전체 텍스트
- `paragraphText`: 현재 selection이 속한 문단 텍스트
- `prefix`: 현재 문단 시작부터 selection 시작 전까지
- `suffix`: selection 끝부터 현재 문단 끝까지

---

## 4. 왜 중요한가

이건 단순한 세부 구현이 아니라, Ghost Complete 품질에 직접 영향을 주는 핵심 기준이다.

문서 전체 기준으로 보내면:

- 앞 문맥이 과도하게 길어질 수 있음
- 현재 문단과 무관한 텍스트가 함께 들어감
- ghost suggestion이 문장 이어쓰기보다 문서 전체 continuation처럼 흔들릴 수 있음

현재 문단 기준으로 보내면:

- 요청 문맥이 짧고 안정적임
- 현재 문장/문단 이어쓰기 목적에 더 맞음
- 이후 인접 문단 문맥을 추가할지 실험적으로 판단하기 쉬움

---

## 5. 실제 반영

`components/editor-workbench.tsx`에서 현재 selection이 속한 `paragraph` node를 찾고,
그 범위 안에서 `paragraphText`, `prefix`, `suffix`를 읽도록 스냅샷 생성 로직을 수정했다.

핵심은 다음과 같다.

- 문서 전체 `prefix` / `suffix` 추출 제거
- 현재 paragraph 범위 계산 추가
- Ghost 요청용 preview는 현재 문단 기준 문맥을 사용

---

## 6. 남은 과제

아직 아래 항목은 남아 있다.

- `Tab` / `Esc` / 추가 입력 / 커서 이동 이벤트 감지 지점 정리
- 현재 문단 기준 추출이 실제 ghost UX 품질에 어떤 영향을 주는지 검증
- 필요 시 인접 문단 일부를 보조 문맥으로 넣을지 재검토

---

## 7. 이후 원칙

앞으로 Ghost Complete 관련 문맥 논의에서는 먼저 아래를 구분한다.

1. **문서 전체 상태를 볼 것인지**
2. **현재 문단 기준 문맥을 보낼 것인지**
3. **추가 문맥이 필요하면 어느 단계에서 확장할 것인지**

현재 MVP에서는 **현재 문단 기준**을 기본 원칙으로 둔다.
