# Ghost 이벤트 감지 기준 정리

- 작성일: 2026-03-29
- 상태: 진행 중
- 관련 범위: editor foundation, ghost complete, interaction

## 1. 문제 상황

현재 문단 기준 `prefix` / `suffix` 추출은 정리됐지만,
Ghost Complete를 **언제 띄우고 언제 숨길지**에 대한 기준은 아직 구현되지 않았다.

이 기준이 없으면:

- 드래그 선택 중에도 ghost가 뜰 수 있고
- 커서가 잠깐 지나가는 위치에서도 불필요한 요청이 나갈 수 있고
- 이후 `Tab` / `Esc` / 추가 입력 무효화 규칙도 흔들릴 수 있다

---

## 2. 이번에 먼저 고정한 기준

초기 규칙은 아래 두 가지로 정리했다.

1. **selection range가 있으면 ghost text는 나타나지 않는다**
2. **collapsed cursor가 같은 위치/문맥에 3초 이상 머물렀을 때만 ghost text가 나타난다**

즉, 현재 단계의 핵심 조건은:

- `selectionStart === selectionEnd`
- 현재 문단 문맥이 바뀌지 않은 상태로 3초 이상 유지

---

## 3. 왜 이렇게 시작하는가

### 드래그 선택 중 ghost 비표시

드래그 중에는 사용자가 이어쓰기보다 선택/이동/편집 범위 확인을 하고 있을 가능성이 높다.

이때 ghost가 뜨면:

- 시각적으로 방해가 되고
- 선택 범위 위에 예측 텍스트가 끼어드는 느낌을 줄 수 있고
- 이후 수락/무효화 조건도 복잡해진다

그래서 **selection range가 있으면 무조건 숨김**을 기본값으로 둔다.

### 3초 dwell 조건

커서가 잠깐 지나가는 순간마다 바로 요청하면:

- 요청 수가 불필요하게 늘고
- ghost가 너무 자주 깜빡이고
- 사용자의 실제 작성 의도보다 빠르게 개입하게 된다

반대로 일정 시간 머문 뒤에만 띄우면:

- 사용자가 잠시 생각 중인 지점을 더 잘 포착할 수 있고
- ghost가 덜 성급하게 나타나고
- 이후 debounce / stale response 방어와도 결합하기 쉽다

이번엔 일단 **3초**를 시작값으로 두고, UX를 보면서 조정하기로 했다.

---

## 4. 실제 반영

`components/editor-workbench.tsx`에서 아래 기준을 구현했다.

- selection이 range면 `isGhostEligible = false`
- selection이 collapsed면 타이머 시작
- 현재 문단 문맥이나 selection이 바뀌면 타이머 리셋
- 3초가 지나면 `isGhostEligible = true`

현재는 이 상태를 실제 ghost 렌더링에 연결한 것은 아니고,
**이벤트 감지 조건을 editor 쪽 state surface로 먼저 만든 단계**다.

---

## 5. 아직 남은 것

이번 구현으로도 아직 아래는 남아 있다.

- `Tab` 수락
- `Esc` dismiss
- 추가 입력 invalidation
- 방향키 / 마우스 클릭 / selection 변경 시 invalidation 세부 규칙
- debounce와 dwell 조건의 관계 정리

즉, 지금 단계는 **ghost를 보여줄 자격이 있는지 판단하는 첫 조건**만 만든 것이다.

---

## 6. 이후 원칙

앞으로 ghost interaction은 아래 순서로 정리한다.

1. **표시 자격 조건**: range selection 아님 + dwell 충족
2. **요청 조건**: debounce / 최신 입력 기준
3. **표시 후 상호작용**: `Tab`, `Esc`, 추가 입력, 커서 이동

현재 MVP에서는 우선
**selection range 숨김 + 3초 dwell**
을 시작 규칙으로 사용한다.
