# Ghost 키 임시 매핑 정리

- 작성일: 2026-03-30
- 상태: 진행 중
- 관련 범위: ghost complete, editor interaction, keyboard events

## 1. 문제 상황

Ghost Complete에서 `Tab`과 `Esc`는 각각

- 제안 수락
- 제안 dismiss

의 핵심 키가 될 예정이지만, 아직 실제 ghost 렌더링과 상태 전이는 완성되지 않았다.

그래서 먼저 확인해야 할 것은:

1. 키 이벤트를 **에디터 레벨에서 직접 받을 수 있는지**
2. ghost가 보이는 상태일 때만 특정 키를 가로채는 구조가 자연스러운지

---

## 2. 이번에 임시로 정한 방식

이번 단계에서는 `editorProps.handleKeyDown`을 사용해
에디터 내부에서 `Tab` / `Esc`를 직접 받도록 했다.

단, 아직은 실제 accept / dismiss 로직 대신
**조건부 `console.log`만 찍는 임시 매핑**으로 둔다.

기준은 다음과 같다.

- `isGhostVisible === true`일 때만 키를 가로챈다
- `Tab`이면 accept placeholder log
- `Esc`면 dismiss placeholder log
- ghost가 안 보이면 기본 키 동작을 그대로 둔다

---

## 3. 왜 에디터에서 직접 받아야 하는가

이 키들은 페이지 전역 단축키가 아니라,
**편집기 내부에서만 의미가 있는 ghost interaction**이다.

그래서 window 전역 keydown보다 editor 쪽에서 직접 받는 것이 더 맞다.

이렇게 하면:

- ghost가 editor 문맥 안에서만 동작하고
- selection / 커서 상태와 더 자연스럽게 연결되고
- 나중에 실제 accept / dismiss 구현으로 교체하기 쉽다

---

## 4. 지금 단계의 의미

이번 구현은 실제 ghost 완성이 아니라
**키 이벤트 surface를 먼저 확보한 단계**다.

현재 되는 것:

- ghost visible일 때 `Tab` 입력 감지
- ghost visible일 때 `Esc` 입력 감지
- 두 경우 모두 placeholder log 출력

아직 안 되는 것:

- 실제 ghost 수락
- 실제 ghost dismiss
- 추가 입력 invalidation
- 커서 이동 invalidation

---

## 5. 구현상 주의점

`useEditor` 설정 안의 key handler는 최신 React state와 바로 맞물리지 않을 수 있다.

그래서 이번에는:

- `isGhostVisibleRef`
- `ghostTextRef`

를 두고, effect에서 최신 값을 ref에 동기화하는 방식으로 임시 연결했다.

즉, 키 이벤트 핸들러는 ref를 통해 최신 ghost 상태를 읽는다.

---

## 6. 다음 연결 포인트

다음 단계에서는 이 임시 매핑을 실제 상태 전이로 바꿔야 한다.

1. `Tab` → `ghostText`를 실제 입력으로 반영
2. `Esc` → `isGhostVisible = false`, `ghostText = null`
3. 추가 입력 → invalidation
4. 커서 이동 → invalidation

현재 MVP에서는 우선
**키 감지 확인 → 상태 전이 연결 → 렌더링 연결**
순서로 진행한다.
